DATA FLOW EXAMPLE: Create Time Study
───────────────────────────────────────────────────────────────────────────────

1. User input:          "Assembly Line A" + Click "Create Study"
2. Frontend:            handleCreateStudy() triggered
3. API Client:          api.createStudy({ process_name: "Assembly Line A" })
4. HTTP Request:        POST http://localhost:8000/api/sampling-spec-rnd/studies/create
5. Backend:             SamplingRnDWorkflow.create_time_study()
6. Database:            Study stored (in-memory or DB)
7. Response:            { success: true, study_id: "study_123" }
8. Frontend:            api.getStudyData("study_123")
9. HTTP Request:        GET http://localhost:8000/api/sampling-spec-rnd/studies/study_123/data
10. Backend:            Returns complete TimeStudy object
11. Frontend:           setSelectedStudy() + display in UI (SamplingCard)

───────────────────────────────────────────────────────────────────────────────
API RESPONSE FORMAT
───────────────────────────────────────────────────────────────────────────────

All responses follow this format:

{
  "success": true,           // Operation succeeded
  "data": { ... },           // Response data (if success)
  "message": "...",          // Message (if success)
  "error": "..."             // Error message (if failed)
}

Example success:
{
  "success": true,
  "data": {
    "study_id": "study_123",
    "status": "draft"
  },
  "message": "Study created: study_123"
}

Example error:
{
  "success": false,
  "error": "Failed to create study"
}

───────────────────────────────────────────────────────────────────────────────
TROUBLESHOOTING
───────────────────────────────────────────────────────────────────────────────

Frontend shows "🟡 Local Storage Mode":
  • Backend might not be running
  • Check if http://localhost:8000/api/sampling-spec-rnd/health responds
  • Check VITE_API_URL in .env

Backend not starting:
  • Make sure Python venv is activated
  • Run: pip install -r requirements.txt
  • Check port 8000 is not in use

API calls failing:
  • Check browser console (F12) untuk error messages
  • Check backend terminal untuk API logs
  • Verify request parameters match API specs
